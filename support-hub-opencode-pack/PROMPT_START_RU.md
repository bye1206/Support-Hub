# Стартовый промпт для OpenCode

Скопируй весь текст ниже в первый сеанс OpenCode из корня репозитория.

---

Ты подключён к проекту **Support Hub**. Прочитай корневой `AGENTS.md` и все документы `docs/`. Это обязательный продуктовый и архитектурный контекст.

## Твоя задача

Помочь перевести Support Hub из стадии проектирования в техническую подготовку и последующую реализацию. Не генерируй весь продукт одним ответом.

### Шаг 1. Аудит текущего состояния

1. Проверь, пустой ли репозиторий, какие файлы уже существуют, есть ли Git-изменения.
2. Не удаляй и не перезаписывай существующие файлы.
3. Сопоставь фактическую структуру репозитория с требованиями из `AGENTS.md` и `docs/`.
4. Проверь внутреннюю согласованность проектных документов. Особое внимание удели:
   - жизненному циклу тикета, диалога и трёхчасовой сессии;
   - владению историей сообщений;
   - связи одного тикета с одним диалогом;
   - обработке Human Handoff и поздних AI-ответов;
   - Outbox, идемпотентности и неопределённым результатам отправки;
   - правам доступа и разделению публичных сообщений/внутренних заметок;
   - согласованности таблиц, API и UI.
5. Не считай проектные примеры API готовыми контрактами внешних систем. Контракт Tag webhook известен только в объёме документа из `docs/04_TAG_AND_BOT_INTEGRATION.md`. Реальный API AI Orchestrator пока нужно получить от владельца существующей системы.

### Шаг 2. Подготовь технический план

Создай или обнови только документацию:

- `docs/implementation/REPOSITORY_AUDIT.md` — что обнаружено в репозитории;
- `docs/implementation/ARCHITECTURE_GAPS.md` — противоречия, пробелы и риски;
- `docs/implementation/IMPLEMENTATION_PLAN.md` — поэтапный план работ с задачами и критериями приёмки;
- `docs/implementation/TECH_DECISIONS.md` — решения, допущения и открытые вопросы.

В плане раздели работы на небольшие этапы:
1. bootstrap репозитория и окружения;
2. конфигурация, логирование, health checks;
3. PostgreSQL, SQLAlchemy, Alembic и первая группа моделей;
4. доменные сервисы и жизненный цикл обращения;
5. Bot/Tag ingress и outbound;
6. AI Orchestrator adapter;
7. operator API и WebSocket;
8. operator UI;
9. admin API/UI;
10. SLA, аудит, hardening, тестирование и deployment.

Для каждого этапа укажи: результат, затрагиваемые модули, зависимости, тесты, критерии готовности и блокеры.

### Шаг 3. Не начинай реализацию без отчёта

На этом первом запуске **не пиши бизнес-код и не создавай миграции**. Сначала представь:

- краткий вывод о состоянии репозитория;
- список найденных противоречий/пробелов;
- план реализации;
- вопросы, без ответов на которые нельзя безопасно идти дальше;
- какой минимальный следующий технический этап предлагаешь.

Если репозиторий пустой, не считай это ошибкой: подготовь план начальной структуры. Не запускай `/init` поверх существующего `AGENTS.md` без необходимости.

### Принцип принятия решений

Подтверждённые решения из `docs/12_DECISION_LOG.md` имеют приоритет. Открытые вопросы перечислены отдельно. Не выдумывай неизвестные детали Tag, Mattermost или AI Orchestrator.

Ключевое бизнес-правило: **одно обращение пользователя = один тикет = один логический диалог**. Не предлагай дробление обращения на несколько тикетов.

Работай на русском языке. Будь конкретным: называй файлы, риски и команды. Не заявляй, что что-либо проверено, пока действительно не выполнил проверку.
