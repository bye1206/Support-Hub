# Промпт: этап 1 — технический bootstrap Support Hub

Используй этот промпт только после того, как ты (OpenCode) прочитал пакет документации, провёл аудит репозитория, подготовил план и владелец проекта согласовал переход к bootstrap.

---

Реализуй **только Этап 1 — Bootstrap** согласно `docs/10_IMPLEMENTATION_ROADMAP.md` и согласованному `docs/implementation/IMPLEMENTATION_PLAN.md`.

## Перед изменениями

1. Проверь `git status`.
2. Повторно прочитай `AGENTS.md` и план.
3. Проверь, что отсутствуют незафиксированные пользовательские изменения, которые можно затронуть.
4. Перечисли файлы, которые собираешься создать или изменить.
5. Не перезаписывай существующие файлы без явного объяснения и безопасного плана.

## Объём этапа

В рамках этого этапа подготовь минимальную запускаемую основу проекта:

- backend skeleton на FastAPI;
- frontend skeleton на React + TypeScript;
- базовую структуру модульного монолита;
- конфигурацию через environment variables;
- `.env.example` без реальных секретов;
- `.gitignore`;
- Docker Compose для локального PostgreSQL, Redis и MinIO (и сервисов приложения, если это согласовано в плане);
- базовые health/readiness endpoints;
- единый формат ошибок и correlation ID, если это укладывается в bootstrap без преждевременной бизнес-логики;
- команды запуска, lint, typecheck и test;
- README с точной инструкцией локального запуска.

## Не делать на этом этапе

- Не реализовывать бизнес-логику тикетов.
- Не создавать все 34 таблицы.
- Не писать миграции бизнес-схемы.
- Не реализовывать интеграцию Tag или AI Orchestrator.
- Не реализовывать операторский или административный функционал.
- Не добавлять Kubernetes, микросервисы, Kafka или ненужную инфраструктуру.
- Не использовать реальные корпоративные адреса, токены или пароли.

## Технические требования

- Python typing и асинхронный FastAPI там, где это оправдано.
- Конфигурация централизована и валидируется при старте.
- Секреты не имеют значений по умолчанию, пригодных для production.
- Контейнеры должны иметь health checks там, где это поддерживается.
- Сервисы должны корректно завершаться (lifespan/shutdown).
- Документируй необходимые команды.

## Проверки

Выполни применимые проверки:
- backend lint/typecheck/tests;
- frontend lint/typecheck/tests/build;
- `docker compose config`;
- запуск контейнеров и проверка health endpoints, если Docker доступен.

Если какая-либо команда не выполнена из-за отсутствия Docker, сети или другого окружения, укажи это честно.
