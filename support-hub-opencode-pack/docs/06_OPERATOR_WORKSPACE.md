# 06. Операторское рабочее место

## 1. Общая компоновка

Основной экран — три колонки:

1. Слева — очереди, фильтры и список тикетов.
2. По центру — публичная история переписки, внутренние заметки и редактор ответа.
3. Справа — карточка тикета, пользователя, назначения, категории, тегов и SLA.

Это desktop-first web UI. На средних экранах правая панель сворачивается; на узких — последовательная навигация между панелями.

## 2. Левая колонка

Быстрые представления:
- все доступные обращения;
- мои обращения;
- без назначения;
- новые;
- в работе;
- ожидают пользователя;
- решённые.

Также отображается общая очередь MVP. Счётчики обновляются realtime. Новый тикет не должен насильно переключать открытый тикет оператора.

Карточка в списке: номер, пользователь, тема, превью последнего сообщения, время активности, статус, приоритет, непрочитанное и SLA-индикатор.

## 3. Центральная колонка

Публичная история показывает сообщения USER, AI, OPERATOR и предназначенные пользователю SYSTEM.

Порядок отображения — `sequence_no`, а не только timestamp.

Отправители визуально различаются. Вложения можно открыть/скачать при наличии прав.

Режим ввода должен явно разделять:
- публичный ответ пользователю;
- внутреннюю заметку сотрудникам.

Нельзя использовать одно неразличимое поле, в котором пользователь может случайно отправить заметку наружу.

## 4. Отправка ответа

1. Оператор пишет ответ.
2. Frontend вызывает Operator API.
3. Backend проверяет права и текущее состояние.
4. В одной транзакции сохраняет сообщение, меняет тикет на PENDING_USER, создаёт Outbox event.
5. Worker отправляет команду боту.
6. UI получает статус доставки.

Ошибка доставки не удаляет сообщение. Оператор видит FAILED/UNKNOWN и безопасный механизм повтора/сверки.

## 5. Правая карточка

Блоки:
- профиль пользователя и подтверждённая корпоративная идентичность;
- статус и приоритет тикета;
- категория и теги;
- очередь и ответственный оператор;
- SLA;
- история назначений;
- история прошлых обращений пользователя.

## 6. Действия

- взять тикет из очереди;
- назначить/переназначить (по разрешению);
- изменить статус;
- изменить приоритет;
- изменить категорию;
- добавить/удалить тег;
- добавить внутреннюю заметку;
- отправить публичный ответ;
- добавить вложение;
- просмотреть SLA и историю действий.

Кнопки показываются по текущему состоянию и правам, но настоящая проверка всегда на Backend.

## 7. Realtime

WebSocket используется для уведомления о новых тикетах, сообщениях, назначениях, изменениях статуса, доставки и SLA. Он не является источником истины. После reconnect frontend синхронизируется REST-запросами.

## 8. MVP

Обязательно: очереди, фильтры, список, карточка, история, публичные ответы, заметки, вложения, назначения, статусы, категория, теги, SLA, история назначений и realtime обновления.
