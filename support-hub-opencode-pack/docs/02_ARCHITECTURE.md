# 02. Архитектура Support Hub

## 1. Архитектурный стиль

Модульный монолит. Не дробить приложение на микросервисы на старте.

## 2. Рекомендуемый стек

| Область | Технология | Статус |
|---|---|---|
| Backend | Python + FastAPI | Выбрано |
| ORM | SQLAlchemy 2.x | Выбрано |
| Миграции | Alembic | Выбрано |
| Validation | Pydantic v2 | Выбрано |
| Database | PostgreSQL | Выбрано |
| Cache/presence/coordination | Redis | Выбрано |
| Background worker | ARQ или другой worker | ARQ — кандидат, проверить и утвердить |
| Frontend | React + TypeScript | Выбрано |
| Files | MinIO | Выбрано |
| Operator SSO | Keycloak + LDAP/AD | Выбрано |
| Reverse proxy | Nginx | Выбрано |
| Packaging | Docker Compose | Выбрано для MVP |
| Tests | Pytest, frontend test tooling | Выбрано/уточнить инструменты |
| Quality | Ruff, mypy/Pyright | Выбрано направление |

## 3. Компоненты и ответственность

### Support Hub Backend

Владеет доменной логикой, транзакциями, API, пользователями, обращениями, историей, SLA, назначениями и авторизацией.

### PostgreSQL

Источник истины для постоянных бизнес-данных: пользователи, идентичности, тикеты, диалоги, сессии, сообщения, вложения (метаданные), назначения, настройки, аудит, события интеграций и Outbox.

### Redis

Временное состояние, присутствие операторов/heartbeat, координация фоновых задач и кэш — согласно выбранной реализации. Не использовать Redis как единственное хранилище пользовательской истории или критичных необратимых событий.

### Worker

Обрабатывает Outbox, интеграционные события, сессии, SLA и другие фоновые задачи. Бизнес-правила должны оставаться в общих сервисах, используемых API и worker.

### MinIO

Закрытое объектное хранилище вложений. В PostgreSQL только метаданные и внутренний ключ объекта. Никаких публичных bucket по умолчанию.

### Mattermost Bot

Существующий транспортный компонент. Принимает Tag webhook и передаёт нормализованные события в Support Hub; отправляет публичные ответы из Support Hub обратно в Tag.

### AI Orchestrator

Существующая независимая система обработки. Внутри неё остаются Pre-process, RAG и Post-process. Support Hub передаёт запрос и необходимый контекст, принимает результат и сохраняет ответ в собственной истории.

### Frontend

Операторское рабочее место и административная панель. Не обращается напрямую к БД, MinIO, Tag или AI Orchestrator.

## 4. Общий обмен

Входящее сообщение:

`Tag → Bot Webhook → Mattermost Bot → Support Hub → PostgreSQL/Outbox → AI Orchestrator`

Ответ ИИ:

`AI Orchestrator → Support Hub callback → PostgreSQL/Outbox → Bot → Tag → пользователь`

Ответ оператора:

`Operator UI → Support Hub → PostgreSQL/Outbox → Bot → Tag → пользователь`

## 5. Ключевые гарантии

- Сохранение сообщения и регистрация необходимого исходящего события выполняются транзакционно.
- Входящие события идемпотентны по внешнему event ID.
- Внешние вызовы не выполняются внутри длинной транзакции БД.
- Для исходящих операций используется Outbox.
- Сетевые повторы могут дать at-least-once delivery; получатель должен поддерживать идемпотентность или сверку результата.
- Перед публикацией AI-ответа проверяются режим и актуальная версия диалога.
- Все критичные изменения состояния выполняются транзакционно.

## 6. Важное ограничение

Документы проекта содержат предложенные endpoints и JSON-примеры. Они не означают, что API с такими маршрутами уже существуют. Реальные контракты существующего бота и AI Orchestrator необходимо изучить до адаптации.
