# 08. Безопасность и доступы

## 1. Операторы

- Keycloak OIDC с корпоративным LDAP/AD.
- Authorization Code Flow + PKCE для browser frontend.
- Проверка подписи, issuer, audience, сроков токена на backend.
- По `sub` определяется локальный `operators` profile.
- Внутренние роли и права проверяются Support Hub.
- Деактивированный оператор не должен выполнять API-запросы даже с ещё действующим токеном.

## 2. Сервисная авторизация

Раздельные учётные данные:
- Bot → Support Hub;
- Support Hub → Bot;
- Support Hub → AI Orchestrator;
- AI Orchestrator → Support Hub.

Секреты не пересекаются с пользовательскими токенами Keycloak и токеном Tag.

## 3. Webhook

Нужно проверить реальный механизм аутентификации callback Tag. Пока не подтверждена подпись/секретный заголовок, использовать HTTPS, сетевое ограничение источников если возможно, сервисную авторизацию на следующем участке Bot → Support Hub, проверку схемы и rate limiting. Не считать payload доверенным только потому, что он пришёл на callback URL.

## 4. Вложения

- MinIO private buckets.
- Случайные object keys; оригинальное имя хранится только как метаданные.
- Проверка размера, расширения и фактического MIME.
- По возможности malware scanning.
- Контролируемый скачивающий endpoint или короткоживущая подписанная ссылка.
- Валидация прав доступа к файлу и связанному тикету.

## 5. Внутренние заметки

- Отдельная таблица/endpoint от публичных сообщений.
- Не включать их в обычную историю пользователя.
- Не передавать AI автоматически.
- Не отправлять в Tag.
- Проверять права на каждое чтение и изменение.

## 6. Аудит

Изменение статусов, назначений, приоритетов, категорий, заметок, ролей и SLA-настроек логируется. Обычная роль приложения не должна иметь UPDATE/DELETE на audit log, где это возможно технически.

## 7. Логи

Не записывать:
- Bearer tokens;
- пароли и секреты;
- полные тела чувствительных webhook без необходимости;
- полное содержимое вложений;
- избыточные персональные данные.

Использовать correlation ID и безопасные диагностические поля.

## 8. Конфигурация

Production secrets не хранятся в Git, в `system_settings` или в примерах. `.env.example` содержит только placeholders.
