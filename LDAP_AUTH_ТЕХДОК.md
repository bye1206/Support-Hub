# ТЕХДОКУМЕНТАЦИЯ: LDAP/AD-авторизация для FastAPI-сервисов
# (HTTP Basic + проверка доменной группы)

Дата: 2026-11-09
Статус: проверено в проде (дашборд RAG-чата, ВМ Linux, ноябрь 2026)
Файлы: `ldap_auth_module.py` (готовый модуль) + этот документ
Зависимости: Python 3.8+, `ldap3>=2.9` (pip install ldap3), FastAPI (для middleware)

================================================================================
1. ЧТО ЭТО
================================================================================
Готовая схема защиты HTTP-эндпоинтов сервиса: пользователь в браузере вводит
ДОМЕННЫЕ логин/пароль (тот же, что для входа в Windows/почту), модуль
проверяет их в корпоративном Active Directory через LDAP(S) и дополнительно
проверяет, состоит ли пользователь в заданной группе безопасности
(например `myapp_users`). Кто не в группе — доступ запрещён, даже с верным
паролем.

Подходит для: внутренних дашбордов, админок, отчётов — любых FastAPI-сервисов,
где нужен вход «по домену + членство в группе».

================================================================================
2. КАК РАБОТАЕТ (СХЕМА)
================================================================================
Браузер ──► GET /admin (нет Authorization) ──► 401 + WWW-Authenticate: Basic
Браузер показывает окно ввода логина/пароля
Браузер ──► GET /admin (Authorization: Basic base64("login:pass"))

Модуль:
  1. Локальный аварийный юзер? (AUTH_LOCAL_USER/PASS, hmac-сравнение) → впустить
  2. Кэш успешных входов? ключ (логин, sha256(пароль)), TTL 15 мин → впустить
  3. AD: bind по UPN (login@corp.tander.ru), LDAPS :636
  4. Self-read: поиск (sAMAccountName=login) в базовом DN → получили DN юзера
  5. Группа: поиск ПО ОБЪЕКТУ ГРУППЫ (member=<DN юзера>) → есть запись = в группе
  6. Успех → кэшируем, пропускаем. Неудача → 401 + запись в лимитер IP
  7. ≥20 неудач с одного IP за 5 мин → 403 (защита от перебора пароля)

ВАЖНЫЕ ОСОБЕННОСТИ НАШЕГО AD (выяснено опытом, учтено в коде):
  a) АНОНИМНЫЙ ПОИСК ЗАБЛОКИРОВАН прокси AD. Нельзя «сначала найти юзера,
     потом проверить пароль». Порядок строго: bind под самим пользователем →
     потом уже поиски.
  b) memberOf В SELF-READ НЕ ПРИХОДИТ (прокси AD вырезает атрибут). Поэтому
     принадлежность группе проверяется «от группы»: ищем записи внутри
     объекта группы по фильтру (member=<DN юзера>), search_scope="BASE".
  c) ldap3 на Debian (2.9.1-2):
     - Tls(validate=ssl.CERT_NONE) — параметр validity= в этой версии НЕ
       работает (тихо игнорируется/ошибка);
     - у Server/Connection используется receive_timeout — параметр
       receive_time_limit есть только в новых версиях;
     - таймаут передавать КАК int. Float (например 10.0) даёт TypeError
       внутри ldap3 при коннекте.

3. БЫСТРЫЙ СТАРТ (3 ШАГА)
================================================================================
ШАГ 1. Положить `ldap_auth_module.py` в проект и поставить ldap3:
       pip install ldap3>=2.9
       (на ВМ: sudo apt install python3-ldap3 ИЛИ pip3 install ldap3;
        в requirements.txt: ldap3>=2.9,<5.0)

ШАГ 2. Подключить к приложению (2 строки):

       from fastapi import FastAPI
       from ldap_auth_module import install_auth

       app = FastAPI()

       install_auth(
           app,
           protected_prefixes=("/admin", "/api/admin"),  # что защищаем
           realm="MyApp",
       )
       # Публичные пути (/health, /api/v1/*, вебхуки) просто НЕ вписываются
       # в protected_prefixes — они останутся открытыми.

ШАГ 3. Задать группу через env и перезапустить сервис. Например в systemd:

       sudo systemctl edit myapp
       ---
       [Service]
       Environment=LDAP_GROUP_DN=CN=myapp_users,OU=Groups,OU=gk,DC=corp,DC=tander,DC=ru
       Environment=AUTH_LOCAL_USER=admin
       Environment=AUTH_LOCAL_PASS=<аварийный пароль>
       ---
       sudo systemctl restart myapp

       БЕЗ LDAP_GROUP_DN модуль пускает ЛЮБОГО доменного юзера — не забудьте!

ПРОВЕРКА: curl -u 'ivanov:P@ssw0rd' https://host/admin/  → 200
          curl -u 'ivanov:неверный' ...                  → 401

4. ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ (вся конфигурация — только env)
================================================================================
Переменная              | По умолчанию                  | Описание
------------------------+-------------------------------+---------------------------
LDAP_HOST               | adldap.corp.tander.ru         | контроллер домена (LDAPS)
LDAP_PORT               | 636                           | порт LDAPS (389 не юзать)
LDAP_DOMAIN             | corp.tander.ru                | домен (для UPN login@домен)
LDAP_BASE_DN            | DC=corp,DC=tander,DC=ru       | корень поиска пользователей
LDAP_GROUP_DN           | (пусто)                       | DN группы доступа. ПУСТО =
                        |                               | любой доменный юзер!
LDAP_TIMEOUT            | 10                            | сек, int (не float!)
AUTH_DISABLED           | (пусто)                       | 1 = выключить auth совсем
                                                      | (только отладка!)
AUTH_LOCAL_USER         | (пусто)                       | аварийный локальный логин
AUTH_LOCAL_PASS         | (пусто)                       | его пароль (работает и при
                                                      | недоступном AD)
AUTH_CACHE_TTL          | 900                           | кэш успеха, сек (15 мин)
AUTH_RATELIMIT_MAX      | 20                            | неудач с IP за окно → 403
AUTH_RATELIMIT_WINDOW   | 300                           | окно лимитера, сек

Как узнать DN нужной группы: попросить у админов AD, либо найти поиском
(пример ниже, раздел 7). Пример DN: CN=myapp_users,OU=Groups,OU=gk,DC=corp,DC=tander,DC=ru

================================================================================
5. КАК ВЕСТИ СЕБЯ ПРИ СБОЯХ (SEMANTICS)
================================================================================
- Fail-closed: если ldap3 не установлен или AD недоступен — проходит ТОЛЬКО
  аварийный локальный юзер. Сервис не остаётся полностью заблокированным.
- Кэш: успешный вход кэшируется на AUTH_CACHE_TTL. Ключ включает sha256
  пароля: смена пароля в AD мгновенно «ломает» кэш-запись (надо снова
  вводить), а старый пароль по кэшу не пройдёт.
- Лимитер: по IP, только НЕУДАЧНЫЕ попытки. Успешный вход ничего не лимитит.
  20 неудач за 5 мин → 403 на последующие попытки с этого IP на окно.
- Пароли НИГДЕ не логируются: detail-строки содержат только описание ошибки
  ldap3, кэш хранит sha256, middleware пароль не пишет в логи.

6. САМОПРОВЕРКА (CLI, без FastAPI)
================================================================================
Модуль можно проверить прямо, без сервиса:

  python3 ldap_auth_module.py ivanov
  Пароль для ivanov: ******
  LDAP: adldap.corp.tander.ru:636  base=DC=corp,DC=tander,DC=ru
  Группа: CN=myapp_users,OU=Groups,OU=gk,DC=corp,DC=tander,DC=ru
  РЕЗУЛЬТАТ: OK — доступ разрешён
  ДЕТАЛИ: ok (group member), dn=CN=Иванов И.И.,OU=Users,DC=corp,DC=tander,DC=ru

Проверять с той машины, где будет жить сервис (к ВМ порт 636 к контроллеру
открыт с серверной сети; с рабочей станции может быть иначе).

Поиск DN группы (если неизвестен) — маленький скрипт:

  import ldap3, ssl, getpass
  u = input("Логин: "); p = getpass.getpass("Пароль: ")
  s = ldap3.Server("adldap.corp.tander.ru", port=636, use_ssl=True,
                   tls=ldap3.Tls(validate=ssl.CERT_NONE), connect_timeout=10)
  c = ldap3.Connection(s, user=f"{u}@corp.tander.ru", password=p, auto_bind=False)
  c.bind()
  c.search("DC=corp,DC=tander,DC=ru", f"(sAMAccountName=*myapp*)",
           attributes=["distinguishedName"])
  for e in c.entries: print(e.entry_dn)

================================================================================
8. БЕЗОПАСНОСТЬ: ЧТО ЗНАТЬ И ЧТО МОЖНО УЛУЧШИТЬ
================================================================================
- TLS-валидация ОТКЛЮЧЕНА (CERT_NONE): у корпоративного прокси цепочка
  сертификатов без промежуточного в стандартных бандлах. Риск: MITM внутри
  сети. Если у проекта есть корпоративный корневой сертификат — включите
  строгую проверку: Tls(validate=ssl.CERT_REQUIRED,
  ca_certs_file="/etc/ssl/certs/corp-root.pem").
- Пароль проходит через память процесса в открытом виде — неизбежно для
  Basic; не логируйте тела запросов/заголовки.
- Basic без HTTPS = пароль в открытом виде по сети. Сервис ДОЛЖЕН быть за
  HTTPS (nginx + сертификат) или использоваться только во внутренней сети.
- Кэш в памяти процесса: рестарт сбрасывает (пользователи просто повторят
  вход). Несколько воркеров — у каждого свой кэш (это ок).
- Логин юзера попадает в логи доступа nginx/web-сервера — это нормально.

9. TROUBLESHOOTING (по опыту эксплуатации)
================================================================================
Симптом                             | Причина / что делать
------------------------------------+-------------------------------------------
bind failed: invalidCredentials     | неверный пароль; или логин с доменом
                                    | внутри ("corp\\ivanov") — надо просто
                                    | ivanov; или учётка заблокирована
user DN not found                   | неверный LDAP_BASE_DN; юзер в другом
                                    | домене/контейнере; учётка отключена
user is NOT a member of the group   | юзер правда не в группе; или неверный
                                    | LDAP_GROUP_DN (проверьте DN поиском,
                                    | раздел 6)
ldap error: unable to open socket   | нет сети до контроллера: DNS, порт 636,
                                    | файрвол. Проверить: nc -zv host 636
ldap error: timeout (долгое висение)| уменьшить LDAP_TIMEOUT; проверить,
                                    | что LDAP_TIMEOUT — int
TypeError при коннекте              | передан float-таймаут — модуль уже
                                    | приводит к int, не меняйте на float
Всё ок в CLI, 401 в сервисе         | AUTH_LOCAL_* перебивает? Проверьте env
                                    | сервиса (systemctl show myapp | grep
                                    | Environment); кэш старого пароля —
                                    | подождать TTL или рестарт
403 всем подряд                     | сработал лимитер (много неудач с IP):
                                    | подождать окно или рестарт сервиса
